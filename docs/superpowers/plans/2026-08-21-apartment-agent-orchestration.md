# Apartment Agent Orchestration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Wire a twice-daily ChatGPT-to-GitHub orchestration loop and a matching Codex execution contract so Codex can autonomously fetch and execute apartment-investment instructions while stopping at material decision points.

**Architecture:** GitHub remains the single shared state between ChatGPT and Codex. ChatGPT reads the current deal/negotiation state and writes one bounded command into `state/next-action.md`; Codex pulls the repo shortly afterward, executes only `STATUS: READY` instructions in the logged-in OLX browser, records outcomes, and transitions the state to `DONE`, `NEEDS_DECISION`, or `BLOCKED`.

**Tech Stack:** GitHub repository state, ChatGPT scheduled automations, Codex browser automation, Markdown state files.

**Spec:** `docs/superpowers/specs/2026-08-21-apartment-agent-orchestration-design.md`

## Global Constraints

- Run the ChatGPT orchestrator at 08:00 and 20:00 Europe/Bucharest.
- Recommended Codex run times are 08:10 and 20:10 Europe/Bucharest.
- GitHub is the shared source of truth; browser/chat history alone is never authoritative.
- Never authorize deposits, reservations, contracts, binding purchase commitments, or disclosure of the user's maximum budget.
- Never arrange an in-person viewing without explicit user approval.
- A seller acceptance, counteroffer, final-offer request, viewing proposal, or material yield/risk change must transition to `STATUS: NEEDS_DECISION`.
- Do not modify `SEARCH_CRITERIA.md` unless the user explicitly asks.
- Preserve historical seller messages and rejected deals.

### Task 2: Add orchestrator operating instructions

**Files:**
- Create: `ORCHESTRATOR.md`

**Interfaces:**
- Consumes: `SEARCH_CRITERIA.md`, `reports/latest.md`, `deals/active.md`, `deals/negotiated.md`, `deals/rejected.md`, `state/next-action.md`, and relevant negotiation files.
- Produces: deterministic instructions for the twice-daily ChatGPT scheduled task.

- [ ] **Step 1: Create `ORCHESTRATOR.md`**

Use this content:

```markdown
# ChatGPT Apartment Orchestrator

## Purpose

At each scheduled run, inspect the current repository state and write one high-value, bounded instruction for Codex into `state/next-action.md`.

## Read order

1. `SEARCH_CRITERIA.md`
2. `reports/latest.md`
3. `deals/active.md`
4. `deals/negotiated.md`
5. `deals/rejected.md`
6. `state/next-action.md`
7. Relevant files under `negotiations/`

## Decision rules

- If `state/next-action.md` is `NEEDS_DECISION`, do not overwrite it with a new seller-facing command unless the decision can be resolved from existing approved investment rules without committing the user financially.
- If a seller accepted, countered, asked for a final offer, or proposed a viewing, preserve `NEEDS_DECISION` and surface the situation to the user.
- If status is `IN_PROGRESS`, do not issue duplicate work.
- If status is `DONE` or `BLOCKED`, inspect the repository and generate the next safe action only when useful.
- Prefer continuing active negotiations over contacting new listings when an active seller reply could materially improve a deal.
- If no active negotiation needs attention, instruct Codex to search for new verified listings that meet `SEARCH_CRITERIA.md`.
- Generate only one primary objective per cycle.

## Command format

Write `state/next-action.md` using the exact contract defined in the orchestration design:

- `STATUS: READY`
- `## Objective`
- `## Instructions`
- `## Stop Conditions`
- `## Safety Limits`
- `## Generated By`
- `## Generated At`

## Safety

Never instruct Codex to:

- pay money;
- reserve a property;
- sign or accept a contract;
- make a binding purchase commitment;
- reveal the user's maximum budget;
- arrange a viewing without explicit user approval.

## Persistence

After writing a materially new `state/next-action.md`, commit and push it. Do not commit if nothing changed.
```
