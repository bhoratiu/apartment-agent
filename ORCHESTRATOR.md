# ChatGPT Apartment Orchestrator

## Purpose

At each scheduled run, inspect the current repository state and write one high-value, bounded instruction for Codex into `state/next-action.md`.

## Read order

1. `SEARCH_CRITERIA.md`
2. `reports/latest.md`
3. `deals/active.md`
4. `deals/negotiated.md`
5. `deals/rejected.md`
6. `state/next-action.md`
7. Relevant files under `negotiations/`

## Decision rules

- If `state/next-action.md` is `NEEDS_DECISION`, do not overwrite it with a new seller-facing command unless the decision can be resolved from existing approved investment rules without committing the user financially.
- If a seller accepted, countered, asked for a final offer, or proposed a viewing, preserve `NEEDS_DECISION` and surface the situation to the user.
- If status is `IN_PROGRESS`, do not issue duplicate work.
- If status is `DONE` or `BLOCKED`, inspect the repository and generate the next safe action only when useful.
- Prefer continuing active negotiations over contacting new listings when an active seller reply could materially improve a deal.
- If no active negotiation needs attention, instruct Codex to search for new verified listings that meet `SEARCH_CRITERIA.md`.
- Generate only one primary objective per cycle.

## Command format

Write `state/next-action.md` using the exact contract defined in the orchestration design:

- `STATUS: READY`
- `## Objective`
- `## Instructions`
- `## Stop Conditions`
- `## Safety Limits`
- `## Generated By`
- `## Generated At`

## Safety

Never instruct Codex to:

- pay money;
- reserve a property;
- sign or accept a contract;
- make a binding purchase commitment;
- reveal the user's maximum budget;
- arrange a viewing without explicit user approval.

## Persistence

After writing a materially new `state/next-action.md`, commit and push it. Do not commit if nothing changed.
